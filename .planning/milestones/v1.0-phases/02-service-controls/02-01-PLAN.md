**2. Add CGO export callbacks in `internal/tray/controller_darwin.go`:**

Add two new `//export` functions after the existing `onQuit` function:

```go
//export onServiceAction
func onServiceAction(cName *C.char, cAction *C.char) {
    if instance == nil || instance.app == nil {
        return
    }
    name := C.GoString(cName)
    action := C.GoString(cAction)
    // Fire-and-forget per D-06: no toast, no spinner.
    go func() {
        switch action {
        case "start":
            instance.app.StartService(name)
        case "stop":
            instance.app.StopService(name)
        case "restart":
            instance.app.RestartService(name)
        }
    }()
}

//export onRefreshStatuses
func onRefreshStatuses() {
    if instance == nil || instance.app == nil {
        return
    }
    statuses := instance.app.GetAllStatuses()
    // Fixed order per D-02: dnsmasq, nginx, php, mysql, postgresql
    serviceOrder := []string{"dnsmasq", "nginx", "php", "mysql", "postgresql"}
    for i, name := range serviceOrder {
        status, ok := statuses[name]
        if !ok {
            status = "not_installed"
        }
        cStatus := C.CString(status)
        C.UpdateServiceStatus(C.int(i), cStatus)
        C.free(unsafe.Pointer(cStatus))
    }
}
```

Key details:
- `onServiceAction` uses the same guard clause pattern as `onShowWindow`/`onQuit`
- The goroutine in `onServiceAction` is fire-and-forget per D-06
- `onRefreshStatuses` iterates in dependency order (D-02) and calls `C.UpdateServiceStatus` for each service, freeing the C string immediately after use (not deferred, since we're in a loop)
- The `C.GoString(cName)` calls do NOT need freeing -- `C.GoString` copies the data into Go-managed memory

Note: `RefreshServiceStatuses` will be implemented in `tray_darwin.m` (Plan 02) as a C function that calls `onRefreshStatuses()` (the Go export). It's declared here so the header is complete for Plan 02.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ObjC -> Go (CGO) | Service names and action strings cross from ObjC menu items into Go callbacks |
| Go -> ObjC (CGO) | Status strings cross from Go backend into ObjC for display |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | onServiceAction cName parameter | accept | Service names originate from hardcoded ObjC arrays (serviceKeys), not user input. The services.Manager.Get() in app.go returns error for unknown names. No external attack surface. |
| T-02-02 | Denial of Service | onServiceAction concurrent goroutines | accept | Fire-and-forget goroutines are bounded by user click rate (menu closes after each click per macOS behavior). No amplification vector. |
| T-02-03 | Information Disclosure | Status strings in menu | accept | Service status (running/stopped) is not sensitive information. Displayed only in local system tray menu visible to the logged-in user. |
</threat_model>
