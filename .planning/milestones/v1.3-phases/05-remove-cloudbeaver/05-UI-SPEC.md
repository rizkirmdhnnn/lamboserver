## Page Layout After Removal

This section defines the visual structure of `PgDatabasePage.tsx` once the CloudBeaver panel is deleted. This is the authoritative post-removal layout.

**Primary visual anchor:** service status card (first visible card in running state). This is the focal point of the page — the running status dot and port detail draw the eye first, communicating service health before any other element.

### Conditional Sections (in render order)

1. **Page header** — always visible
   - Heading: "Database" (22px semibold)
   - Sub-text: "Manage PostgreSQL databases" (13px, `--text-secondary`)
   - Refresh button: btn-secondary btn-sm, top-right, `<RefreshCw size={14} /> Refresh`

2. **Error banner** — visible only when `error !== null`
   - Card with left border `3px solid var(--danger)`
   - 13px text, `--text-secondary`

3. **Not installed state** — visible when `!installed`
   - `.card .empty-state` layout
   - `<Database size={32} />` icon
   - Heading: "PostgreSQL is not installed"
   - Body: existing install description copy (unchanged)
   - CTA button: "Install PostgreSQL" (btn-primary) → transitions to install step label

4. **Installed but stopped state** — visible when `installed && !running`
   - Single `.card` with `.service-row`
   - Status dot: stopped (red, no glow)
   - Service name: "PostgreSQL", detail: "Stopped"
   - Button: "Start" (btn-primary btn-sm)

5. **Running state** — visible when `installed && running`
   - Service controls card: status dot running (green glow), "Running · Port 5432 · Socket: postgres (trust auth)", "Stop" button (btn-danger btn-sm)
   - Create Database card: text input + "Create" button (btn-primary btn-sm) with `<Plus size={14} />`
   - Databases list card: table of user databases with name/size/drop columns, or "No databases yet — create one above" (muted text) when empty

6. **Drop confirmation modal** — visible when `dropTarget !== null`
   - Fixed full-screen overlay `rgba(0,0,0,0.5)`
   - Inner `.card` max-width 400px
   - See Copywriting Contract for exact copy

**The CloudBeaver section (formerly item 6 in the original file, lines 357–415) is fully deleted. No placeholder, no "Coming soon", no empty card.**

## Copywriting Contract

Source: existing copy in PgDatabasePage.tsx. No new copy required for this removal phase.

| Element | Copy |
|---------|------|
| Page heading | Database |
| Page sub-heading | Manage PostgreSQL databases |
| Not installed heading | PostgreSQL is not installed |
| Not installed body | Install PostgreSQL 17 from pre-built binaries. This downloads the binary, extracts it, and initialises the data directory. |
| Install CTA | Install PostgreSQL |
| Install in-progress (download) | Downloading... |
| Install in-progress (init) | Initializing... |
| Install complete | ✓ Installed |
| Start button | Start |
| Starting in-progress | Starting... |
| Stop button | Stop |
| Stopping in-progress | Stopping... |
| Running detail | Running · Port 5432 · Socket: postgres (trust auth) |
| Stopped detail | Stopped |
| Create database CTA | Create |
| Creating in-progress | Creating... |
| Databases empty state | No databases yet — create one above |
| Drop confirmation heading | Drop Database |
| Drop confirmation body | Are you sure you want to drop "{name}"? This action cannot be undone. |
| Drop confirmation cancel | Keep Database |
| Drop confirmation confirm | Drop Database |
| Drop in-progress | Dropping... |
| Error banner | Could not load database status. Check that PostgreSQL is running, then refresh. |

Destructive actions in this phase:
- **Drop Database**: inline confirm modal — no separate page. Dismiss button "Keep Database" preserves state. Confirm button uses btn-danger. Copy: "This action cannot be undone."
- **Stop PostgreSQL**: no confirmation modal — single button click. Uses btn-danger to signal consequence.

No new destructive actions introduced by this phase. The Stop CloudBeaver / Install CloudBeaver / Open CloudBeaver buttons are deleted — no confirmation needed for deletion of UI elements.
