Create `scripts/build-dmg.sh` following the exact structure from 09-PATTERNS.md. The script must contain:

**Shebang and error handling (line 1-2):**
```bash
#!/bin/bash
set -e
```

**Variable declarations (lines 4-8), matching generate-icns.sh pattern -- plain assignment, no export:**
```bash
APP_NAME="LamboServer"
VERSION="1.0.0"
APP_PATH="build/bin/${APP_NAME}.app"
DMG_OUT="${APP_NAME}-${VERSION}.dmg"
ENTITLEMENTS="build/darwin/entitlements.plist"
```

**Step 1 -- Build universal .app (per D-02, D-03):**
```bash
echo "[1/4] Building universal .app..."
wails build -platform darwin/universal -clean
```

**Step 2 -- Ad-hoc sign with entitlements (per D-04, D-05, D-06):**
```bash
echo "[2/4] Ad-hoc signing with entitlements..."
codesign --force --deep -s - --entitlements "${ENTITLEMENTS}" "${APP_PATH}"
codesign --verify --deep "${APP_PATH}"
echo "  Signature verified"
```
- `--force` is required because wails build pre-signs the bundle (PITFALLS Pitfall 1)
- `--deep` signs nested binaries (acceptable for ad-hoc per RESEARCH.md)
- `-s -` is ad-hoc identity per D-04
- `--entitlements` embeds the plist per D-05 (without this, entitlements are empty)
- Verify step confirms signature is valid before proceeding to DMG

**Step 3 -- Package DMG (per D-07, D-08, D-09):**
```bash
echo "[3/4] Packaging DMG..."
STAGING=$(mktemp -d)
trap "rm -rf ${STAGING}" EXIT
cp -r "${APP_PATH}" "${STAGING}/"
ln -s /Applications "${STAGING}/Applications"
hdiutil create \
  -volname "${APP_NAME}" \
  -srcfolder "${STAGING}" \
  -ov \
  -format UDZO \
  "${DMG_OUT}"
```
- `mktemp -d` creates staging in /tmp/ to avoid "resource busy" (PITFALLS Pitfall 4)
- `trap ... EXIT` ensures cleanup even on error with `set -e`
- `ln -s /Applications` creates the drag-to-Applications alias per D-09
- `-volname "LamboServer"` (Claude's Discretion -- product name)
- `-srcfolder` avoids mount/unmount loop (RESEARCH anti-pattern)
- `-ov` overwrites existing DMG for idempotent builds
- `-format UDZO` is zlib-compressed read-only DMG (standard distribution format)
- DMG output is project root, NOT build/bin/ (PITFALLS Pitfall 2)

**Step 4 -- Done message:**
```bash
echo "[4/4] Done. Output: ${DMG_OUT}"
```

After creating the file, make it executable: `chmod +x scripts/build-dmg.sh`

**Anti-patterns to avoid (from RESEARCH.md):**
- Do NOT use `--options runtime` (enables Hardened Runtime, incompatible with ad-hoc per D-06)
- Do NOT write DMG to `build/bin/` (deleted by `-clean`)
- Do NOT use `hdiutil attach` + manual copy loop (use `-srcfolder`)
- Do NOT include icon generation step (per D-03)
- Do NOT include functions, conditionals, or loops (match generate-icns.sh flat structure)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build script -> system tools | Script invokes codesign, hdiutil, wails as external processes |
| Signed .app -> end user machine | Users download and run the signed .app from DMG |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | .app bundle after signing | mitigate | codesign --verify --deep in build-dmg.sh validates signature integrity before DMG packaging |
| T-09-02 | Tampering | entitlements.plist modification | accept | File is committed to git; changes are tracked via version control; ad-hoc signing means entitlements are self-asserted anyway |
| T-09-03 | Spoofing | Gatekeeper bypass instructions could be mimicked by malware | mitigate | DOC-01 documents the exact System Settings path so users know the legitimate workaround (Plan 02) |
| T-09-04 | Tampering | DMG contents modified after creation | accept | DMG is read-only (UDZO format); modification requires re-creation; no code signing on the DMG itself (standard for ad-hoc distribution) |
| T-09-05 | Elevation of Privilege | build-dmg.sh runs with user privileges | accept | Script uses no sudo; all tools run as current user; no privilege escalation vector |
</threat_model>
